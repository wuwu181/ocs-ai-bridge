# 故障排查

先运行 `diagnose.cmd`，再在控制台“在线试答”查看具体错误。诊断只检查本机环境，不调用付费模型，不输出 Key。

| 现象 | 检查和处理 |
| --- | --- |
| 提示找不到 node | 安装 Node.js 22+，关闭终端后重新打开；运行 `node --version` |
| 双击窗口一闪而过 | 在 PowerShell 进入解压目录，运行 `.\start.cmd`，保留错误信息 |
| 浏览器打不开 | 保持服务窗口运行；使用窗口显示的地址；端口占用时可能顺延 |
| 页面要求登录 | 使用本机 `.env` 的 `OCS_BRIDGE_TOKEN`；也可再次运行启动器打开登录链接 |
| 点击连接无反应，网址变成 `/?` | 升级到3.0.1以上。旧V2进程读取新版网页时，无法提供扩展脚本，旧版静态导入会阻断登录事件。关闭旧服务，重新运行新版start.cmd，再Ctrl+F5刷新。3.0.1已将扩展按需加载，旧服务会显示升级提示 |
| 本机 HTTP 401 | OCS 中的本机 token 过期或不匹配；从“连接 OCS”重新导出并导入 |
| 上游 HTTP 401 / 403 | 核对服务商、Key、完整 URL、鉴权方式和账号模型权限；本机 token 不能代替服务商 Key |
| 上游 402 / 429 | 检查服务商余额、额度或频率限制，减少 OCS 并发 |
| model not found / 404 | 确认模型 ID 属于这个平台、账号有权限，且 URL 是完整端点 |
| 没有可用模型 | 检查接口已启用、已保存 Key、路由包含该接口；自建无鉴权模型选择“无鉴权” |
| 图片题没有可用模型 | 接口要支持视觉并开启图片能力；把它加入图片路由，使用自动 / 完整模式 |
| 缺少图片 / blob 地址无效 | OCS 开启图片题优化，刷新页面重试；优先让浏览器传 Base64 图片 |
| 答案被截断 | 提高该模式输出上限；复杂解答使用完整模式；推理模型可能需要更大的上限 |
| JSON 参数不支持 | 按平台能力关闭完整模式 JSON Mode，检查额外请求体和 token 参数名 |
| Claude 版本或鉴权错误 | 检查 Messages 协议、anthropic-version，以及服务商要求的 x-api-key / Bearer |
| 模型列表查询失败，但试答正常 | 部分兼容端没有 `/models`，直接填写平台文档中的模型 ID |
| OCS 超时 / 排队已满 | 降低并发，使用省 Token 或更快模型，减少候选；默认总预算 50 秒 |
| Key 输入框保存后为空 | 页面不会回显 Key；留空保留旧值，查看已设置状态即可 |
| Token 图表为空 | 服务商未返回 usage 或尚无请求；数据仅保存在本次进程内 |

## 区分健康检查与模型调用

`GET /health` 和 OCS 的 `GET/HEAD` 检测不会调用模型，也不验证服务商 Key。健康状态里的 `upstream_checked:false` 是正常行为。模型错误应以在线试答或实际答题返回的错误为准。

某些 OCS 版本的 HEAD 检测不携带 Authorization。使用本项目生成的本机配置可独立处理健康检测；不要仅凭题库指示灯判断付费 API 的可用性。
